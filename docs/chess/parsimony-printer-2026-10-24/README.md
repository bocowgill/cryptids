# Bounded Parsimony packet-printer pilot

User authorization: October 24, 2026, a bounded printer pilot on the exact existing
chess packet, fully paid state accounting and net-savings assessment before
certification. The older body-quotient goal remains paused. No Lean proof work,
broader search, new goal/automation, paid infrastructure or outreach is included.

The accepted baseline is 769,344 states at `100ed947d612079dc454070189e506efc2b7a780`.
Its writer uses 173,642 states; the retained suffix uses 595,702. The experimental
310,029-state body-quotient construction is excluded from accepted savings.

The packet comes verbatim from the accepted and pinned
`docs/chess/campaign-2026-10-22/round-04/evidence/packet-02/unpacked/packet.bits`.
It contains 173,641 ASCII bits; SHA-256:
`ab1f8764749765bfb0d44b22a999d7907345d2648bf478092a276cf8df71c2d8`.
The accepted full-run manifest independently names that exact packet checksum.

Parsimony is pinned at `7c199dbe0c82f0b9cc1adfbdc2b48fee3fef53aa`:
https://github.com/adamyedidia/parsimony/tree/7c199dbe0c82f0b9cc1adfbdc2b48fee3fef53aa

`upstream/programmer.py` and its MIT license are byte-identical to upstream Git
blobs `6c97f0c4b63ee391978e40befb0cca1a919dd6cf` and
`b4b7deb7dbbbcfbf7c7cb4d51b323db9eb45f7a0`. The adapter extracts the unchanged
Python-3-compatible printer routines without invoking Laconic, ANTLR or the
Python-2-only command-line wrapper. The supported State shim preserves all
explicit read/write/movement commands. Default ERROR transitions lead to one
explicit paid nonhalting trap; tests must never enter it. The bridge is initially
a counted diagnostic boundary, not a claimed certified connection.

See [GATES.md](GATES.md) for the predeclared contract and maximum two-run budget.
The first run checks native and independent Python physical executions on all
8-bit words plus wider fixtures, reconstructs the exact entire chess packet
from emitted transition targets, counts every raw control, and probes the full
printer under a fixed step/time bound. The physical tape/head receipts determine
the exact cleanup and connection work that must be built and counted next.
An incomplete full-printer probe is reported honestly, not as successful startup.

Only the new workflow-file path triggers the first run on push. Subsequent
checkpoint commits do not restart it; any second run is manually dispatched only
after diagnosing a concrete obstruction. Sources, numeric tables, fixture tapes,
logs, corruption controls, resource outcomes and exact run identities are retained.

No new state count is certified by this pilot. Even a positive measured saving
requires a later generic extractor/output-boundary proof and composition with
the unchanged full chess halting theorem, plus full state/fixture/foundation checks.
