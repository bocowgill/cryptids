# OpenEvolve compiler pilot

Target one routine: binary lowering of a Post write entering its distinguished
terminal control. Omit that control’s return state. Certified saving: one state,
392,046,822 to 392,046,821, with the full 3,110,360-state initializer counted.
The actual machine and count passed strict remote Lean checks. Completed pilot
acceptance and the separate successful baseline recovery are recorded in RESULTS.md.

Preserve the frozen strategic target and all 192 accepted M7 source/tool/artifact
inputs in baseline-pins.json. No chess-value claim, implementation beyond M7,
or outreach is authorized by this pilot. The new module changes compilation only.

The proof relates live boundaries by exact encoded tapes. At terminal boundaries
it relates only the terminal control: the final head may be one cell to the right.
Positive-length simulation and matching stopping yield both halting directions.

Use actual OpenEvolve commit 59dfe764b5ab4478ac00214432fcac33bbe2bf4b, not a
home-grown loop bearing its name. Candidate files contain a strict data grammar;
never execute generated Python. The supplied family controls terminal-write and
nonterminal-write lowering. Baseline plus incorrect proposals are controls.
A smaller program may be certified only after its universal Lean contract passes.
Proof timeout/failure is a rejection, never evidence of falsehood or correctness.

The actual model run used public Qwen2.5-Coder-0.5B-Instruct on a remote GitHub
Actions CPU runner, with no paid inference API. Its exact revision, five proposals,
token counts, wall time, responses, feedback, checkpoints and dependency versions
are retained with the core evidence. We supplied this optimization family; its
invention is not attributed to the model.

All compilation, proofs, native execution, search and model inference run remotely.
Local operations are editing, light metadata/hashes and orchestration. Reproduction
must report actual completed checks and distinguish proof from finite fixtures.
